# 製品要求仕様書（PRD）：Semcrawl

## 1. 概要とビジョン

### 1.1 課題
従来のWebスクレイピングでは、具体的なCSSセレクターやXPath式に強く依存する、サイトごとの壊れやすい実装が必要です。Webサイトのレイアウトやクラス名が変わるとスクレイパーはすぐに動かなくなり、手作業での高コストな修正が必要になります。さらに、単独のスクリプト間でヘッドレスブラウザーのライフサイクルを管理することは、リソースのリークや煩雑なボイラープレートコードの原因となりがちです。

### 1.2 ビジョン
**Semcrawl**は、**Jev**による評価を活用したセマンティックWebスクレイピングを実現します。ハードコードされたCSSセレクターや壊れやすいDOMパスに頼る代わりに、セマンティックな意味と構造上の役割（例：`page.semantic("検索結果 > 商品一覧 > 商品")`）に基づいて、関連するDOMノードを動的に特定します。

サイト固有の構造を直感的なセマンティッククエリに抽象化し、オンデマンドで動作するバックグラウンドデーモンとセッションベースのGo製CLIを提供することで、Semcrawlは堅牢で並行処理が可能な、複数言語から利用できるWebスクレイピングを可能にします。

---

## 2. 対象ユーザーとユースケース

- **対象ユーザー：** 堅牢で保守しやすいスクレイピングパイプラインを必要とする、さまざまなプログラミング言語（Ruby、Python、Go、Node.jsなど）を利用する開発者（バックエンド開発者、データエンジニア、自動化の専門家）。
- **主なユースケース：**
  - **動的なECサイトのスクレイピング：** サイトごとに専用パーサーを保守することなく、さまざまなオンラインストアから商品一覧、商品名、価格、在庫状況を抽出する。
  - **コンテンツ集約：** UIのリファクタリングに自動で適応する記事、掲載情報、検索結果を収集する。
  - **言語に依存しないスクレイピングスクリプト：** 任意の言語（CLIコマンドを呼び出すRubyスクリプトなど）で慣用的なスクレイパーを書き、ブラウザーのライフサイクル、セッションの分離、DOMの分類をSemcrawlに任せる。

## 3. システムアーキテクチャ

Semcrawlは、オンデマンドのデーモンライフサイクルとセッション分離を備えた、**デーモン＋CLI**アーキテクチャで動作します。

```
+-----------------------------------------------------------+
| 複数言語のSDK／スクリプト（Ruby、Python、Shellなど）       |
+-----------------------------+-----------------------------+
                              | <session_id> を指定してCLIコマンドを呼び出す
                              v
+-----------------------------------------------------------+
|                   Semcrawl CLI（Goバイナリ）              |
|  - デーモンが未起動の場合は自動で起動する                 |
+-----------------------------+-----------------------------+
                              | IPC／Unixソケット／HTTP
                              v
+-----------------------------------------------------------+
|                 Semcrawlデーモン（Goプロセス）             |
|                                                           |
|  +-----------------------------------------------------+  |
|  | セッションマネージャー                               |  |
|  | - セッションの分離（タブ／ブラウザーコンテキスト）   |  |
|  | - アイドルタイムアウト／自動クリーンアップ          |  |
|  +-----------------------------------------------------+  |
|                                                           |
|  +--------------------+             +------------------+  |
|  | ブラウザー制御      |             | Jevセマンティック |  |
|  | （Chrome CDP／     | <=========> | 評価エンジン      |  |
|  |  Firefox BiDi）     |             |                  |  |
|  +--------------------+             +------------------+  |
|           |                                               |
|           v（将来：軽量HTTP／curlフェッチャー）            |
+-----------------------------------------------------------+
```

### 3.1 コンポーネント

1. **Semcrawl CLI：**
   - 起動中のデーモンと通信する軽量なコマンドラインインターフェース。
   - デーモンが未起動の場合、バックグラウンドで透過的に自動起動する（`semcrawl open` 経由）。
   - パイプラインで簡単に解析・連携できるよう、構造化されたJSONを `stdout` に出力する。
2. **Semcrawlデーモン ＆ セッションマネージャー：**
   - ブラウザーセッションを管理する常駐バックグラウンドプロセス（CDP経由のChrome、WebDriver BiDi経由のFirefox）。
   - 一意の `session_id` トークンで識別される個々の**セッション**を管理し、ブラウザーコンテキスト、タブ、クッキーを分離する。
   - セッションごとのアイドル時間を監視し、設定可能なタイムアウト後にブラウザーリソースを自動的に解放する。
   - アクティブなセッションが0件の状態が一定時間続いた場合、デーモンプロセス自体を自動終了する。
   - 差し替え可能なフェッチャー層を備える。完全なヘッドレスブラウザーに対応し、レンダリングが不要な場合に軽量なHTTPフェッチャー（curl／HTMLパーサーなど）を利用できるよう設計する。
3. **Jevセマンティック評価エンジン：**
   - 候補となるDOM要素がクエリで指定されたセマンティックな条件を満たすか評価する。
   - 独立して再利用でき、信頼性の高い外部Jevライブラリや軽量なGoネイティブバインディングと連携できる。

## 4. 主な機能要件

### 4.1 オンデマンドのライフサイクルとセッション管理
- **デーモンの自動起動：** `semcrawl open` 実行時にデーモンが動いていない場合、CLIが自動的にデーモンプロセスを起動する。
- **セッションライフサイクル：**
  - `open`: 独立したブラウザーセッション／コンテキストを作成し、一意の `session_id` を返す。
  - `close`: 指定したセッションを破棄し、関連付けられたブラウザーページ／コンテキストを解放する。
  - `session list`: アクティブなセッションとその状態／アイドル時間を一覧表示する。
- **アイドルタイムアウトと自動クリーンアップ：**
  - 一定時間（デフォルト例：5〜10分）リクエストがないセッションを自動終了する。
  - アクティブなセッションが0件の状態で一定時間（例：15分）経過した場合、デーモンを自動シャットダウンする。
- **明示的なデーモン制御：** デバッグ、監視、明示的なシステム管理のために、`semcrawl daemon start`、`status`、`stop` を引き続き提供する。

### 4.2 ページ遷移と操作
- セッションスコープで指定したURLへ遷移する（`goto <session_id> <url>`）。
- セッションスコープで基本的なユーザー操作（クリック、スクロール、文字入力）を実行し、状態とコンテキストを維持する。

### 4.3 セマンティッククエリとDOM走査
- **階層型セマンティックパスクエリ：**
  - パンくずリストに似た構文（`"検索結果 > 商品一覧 > 商品"`）をサポートする。
  - アクティブなセッションのDOM内で上位から順に走査する：
    1. 最初の区分（例：「検索結果」）に一致するコンテナーを特定する。
    2. そのコンテナー内で、繰り返し項目を含むリストコンテナー（例：「商品一覧」）を特定する。
    3. 繰り返し表示される項目（例：「商品」）を特定し、一致したノードIDの配列を返す。
- **サブ要素の属性とテキストの抽出：**
  - 解決済みのノードに対して、指定フィールド（例：`"商品名, 価格"`）を抽出する。
  - フィールドごとに、テキスト内容や `href`、`src` などの属性を含む構造化データを返す。

### 4.4 複数言語から利用しやすい出力
- すべてのCLIコマンドでJSON形式の出力をサポートし、明確なステータスコードとエラーメッセージを返す。

## 5. CLIとSDKのインターフェース設計

### 5.1 CLIコマンド

```bash
# セッションのライフサイクル（デーモン未起動時は自動起動）
semcrawl open [--headless] [--browser=chrome|firefox]
# 出力例: {"session_id": "abc123", "status": "ready"}（プレーンテキストモードではセッションIDのみ出力）

# ページ遷移
semcrawl goto abc123 "https://example.com/search?q=laptop"

# セマンティッククエリ（ノードIDの一覧をJSONで返す）
semcrawl query abc123 "検索結果 > 商品一覧 > 商品"

# ノードからのデータ抽出
semcrawl extract abc123 <node_id> "商品名, 価格"

# クエリと抽出をまとめて実行するコマンド
semcrawl extract abc123 --query "検索結果 > 商品一覧 > 商品" --fields "商品名, 価格"

# セッション終了
semcrawl close abc123

# セッションおよびデーモン管理
semcrawl session list
semcrawl daemon status
semcrawl daemon stop
semcrawl daemon start [--headless] [--browser=chrome|firefox]
```

### 5.2 複数言語向けSDKの構想（Rubyの例）

セッションベースのアーキテクチャにより、各プログラミング言語の慣行（例：ブロック構文によるスコープ管理）に自然に適合します。

```ruby
Semcrawl.open("https://example.com/search?q=laptop") do |page|
  # 内部的な実行フロー:
  # session_id = semcrawl open
  # semcrawl goto <session_id> <url>
  products = page.semantic("検索結果 > 商品一覧 > 商品")
  
  products.each do |product|
    data = product.semantic("商品名, 価格")
    puts "#{data['商品名']}: #{data['価格']}"
  end
  # ブロック終了時に自動で呼び出し: semcrawl close <session_id>
end
```

## 6. 非機能要件

- **性能と効率：**
  - 候補となるDOMノードを絞り込む（script／styleタグ、空のコンテナー、非表示要素などを除外する）ことで、Jevの評価負荷を抑える。
  - CLIとデーモン間の低遅延なIPC（UnixドメインソケットまたはローカルHTTP／gRPC）。
  - セッションのアイドル自動クリーンアップにより、メモリリークやゾンビ化したブラウザープロセスを防止する。
- **拡張性：**
  - フェッチャーを抽象化し、フルブラウザー（CDP／BiDi）と高速な静的HTTPフェッチャーを簡単に切り替えられるようにする。
  - Jevとの連携層をモジュール化し、評価方式を交換・更新できるようにする。
- **移植性：**
  - Linux、macOS、Windowsで動作する、単独実行可能なGo製バイナリとして配布する。

## 7. 今後の機能拡張（ロードマップ）

1. **セレクターのキャッシュと自己修復：**
   - Jevが具体的なDOMセレクターパスを特定した後、そのパスをキャッシュし、以降のクエリで再利用してスクレイピングを高速化する。
   - キャッシュしたセレクターが機能しない場合は、Jevによる再評価に自動で切り替える（自己修復するスクレイパー）。
2. **軽量なヘッドレスHTTPフェッチャー：**
   - ヘッドレスブラウザーによるレンダリングが不要な静的ページ向けに、curl／HTTPクライアントモードを追加する。
3. **公式クライアントバインディング：**
   - ブロック構文によるセッションの自動クリーンアップを組み込んだ、最小限で各言語の慣習に沿ったgem／パッケージ（Ruby、Python、Node.js）を提供する。
